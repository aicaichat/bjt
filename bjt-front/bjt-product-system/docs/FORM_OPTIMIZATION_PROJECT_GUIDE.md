# BJT 产品管理系统表单优化项目实施指南

## 📋 项目概览

### 1.1 项目背景
BJT 产品管理系统的管理页面表单存在以下核心问题：
- **下拉菜单数据不匹配**：硬编码选项与实际业务需求不符
- **字段关联错误**：缺少产品线与产品类型的动态关联
- **用户体验差**：缺少智能提示、字段验证和默认值
- **维护成本高**：每个页面独立维护字段配置，重复代码多

### 1.2 项目目标
通过渐进式改进，实现：
- ✅ **数据一致性**：字段配置与数据库结构100%匹配
- ✅ **智能化体验**：基于产品线的动态字段显示和验证
- ✅ **标准化管理**：统一的字典数据管理和表单组件
- ✅ **可维护性**：降低80%的表单维护成本

### 1.3 涉及范围
- **前端页面**：机器、配件、耗材、备件的新增/编辑页面
- **后端API**：字典数据接口和表单配置接口
- **数据库**：字段映射规则和业务配置
- **组件库**：智能表单组件和验证工具

## 🔧 技术实现详情

### 3.1 后端字典API设计

**接口路径**：`/wp-json/bjt/v1/dictionaries/{type}`

**支持的字典类型**：
- `units` - 单位：件、卷、箱、套等
- `voltages` - 电压：110V、220V、380V、440V
- `frequencies` - 频率：50Hz、60Hz
- `statuses` - 状态：草稿、已发布、回收站、私有
- `brands` - 品牌：BJT、Lockedair、PakTech、通用
- `bag_types` - 袋型：MEX型、B4型、MEE型等
- `countries` - 国家：中国、美国、英国等
- `user_roles` - 用户角色：管理员、经理、编辑员、用户
- `product_types` - 产品类型：主机、配件、耗材、备件

**返回格式**：
```json
{
  "success": true,
  "data": {
    "type": "units",
    "items": [
      {"code": "pcs", "name": "件"},
      {"code": "roll", "name": "卷"}
    ]
  }
}
```

### 3.2 前端组件API设计

**DictionarySelect 组件属性**：
```typescript
interface DictionarySelectProps {
  dictionaryType: string;        // 字典类型
  value?: string;               // 当前值
  onChange?: (value: string) => void; // 变更回调
  placeholder?: string;         // 占位符
  allowClear?: boolean;         // 允许清除
  disabled?: boolean;           // 禁用状态
  mode?: 'multiple' | 'tags';   // 多选模式
  lang?: 'zh' | 'en';          // 语言
}
```

**使用示例**：
```tsx
<DictionarySelect
  dictionaryType="units"
  placeholder="请选择单位"
  value={formData.unit}
  onChange={(value) => setFormData({...formData, unit: value})}
/>
```

### 3.3 数据流图

```
CSV文件数据 → 字典控制器 → REST API
                               ↓
用户操作 → DictionarySelect → 字典服务 → API请求
                ↓
表单组件 ← 下拉选项数据 ← 组件状态
```

## 🤖 自动化国际化改造执行策略

### 1. 全自动推进，无需人工干预
- 由 AI 助理根据业务优先级和依赖自动选择下一个模块和页面。
- 每个页面自动完成：
  - 自动查找/创建/补全翻译文件（如 accessories.json）
  - 自动替换所有硬编码文字为国际化调用（t('xxx', { ns: 'accessories' })）
  - 自动集成多语言输入组件（如 MultilingualInput）
  - 自动生成变更说明和验收清单
- 不再每步询问用户，中间过程无需人工确认。
- 只在全部 P0 模块完成后，输出所有变更点、翻译文件 diff、验收自查清单。

### 2. 执行顺序
- 先主业务模块（主机、配件、备件、耗材），每个模块先做列表页，再做编辑页，再做特殊页。
- 完成一个模块的所有页面后，自动进入下一个模块。

### 3. 质量保障
- 每步自动检查类型报错、key 显示、语言切换、功能回归。
- 发现问题自动修复，直至通过验收标准。

### 7.4 命名空间注册与国际化调用经验

**问题现象**：页面出现 accessories:list.title 这类 key 原样显示，或中英文切换无效。

**根因分析**：
- i18n 实例未注册 accessories 命名空间，或 useTranslation 只注册了 common/forms，导致 accessories.json 未被加载。
- 国际化调用方式错误（如 tc('accessories:fields.id')），未用标准 t('fields.id', { ns: 'accessories' })。

**最佳实践**：
- useTranslation(['common', 'forms', 'accessories']) 注册所有需要的命名空间。
- 国际化调用统一用 t('xxx', { ns: 'accessories' })，保证 key 能被正确解析和切换。
- 新增命名空间时，需在 i18n 初始化和 useTranslation 中同步注册。
- 遇到 key 显示异常，优先排查命名空间注册和 key 写法。

**自动化修复流程**：
- 检查并补全 useTranslation 的命名空间数组。
- 批量替换所有国际化调用为标准写法。
- 自动检测页面 key 显示和语言切换效果，发现异常自动修正。
