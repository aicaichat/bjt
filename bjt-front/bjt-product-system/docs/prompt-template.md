# AI Prompt Template

> 使用本文档作为撰写/更新任何 AI Prompt 的标准格式，确保不同主题的 Prompt 具备一致结构、便于理解与迭代。

---

## 1️⃣ 基本信息

| 字段 | 说明 |
|------|------|
| **Prompt 名称** | 建议使用 kebab-case，例如 `checkout-payment-prompt` |
| **版本** | 如 `v1.0.0`；更新需在修订历史记录 |
| **最后更新** | 日期 + 作者 |
| **适用模型** | GPT-4o / Claude-3 / 遇到限制时说明 |

---

## 2️⃣ 使用场景（Context）
简要说明业务背景、使用此 Prompt 的场合及期望解决的问题。

---

## 3️⃣ 目标（Objective）
明确 AI 执行的核心目标或产出，例如：
- 生成插件骨架代码
- 编写测试用例
- 输出接口文档

---

## 4️⃣ 输入参数（Inputs）
列举用户或系统需提供给 AI 的所有关键信息：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `api_spec` | Markdown | ✓ | REST API 规格 |
| `style_guide` | Markdown | ✗ | 代码风格指南 |
| … | … | … | … |

> **提示**：若参数较多，可附 YAML 示例。

---

## 5️⃣ 约束（Constraints）
- 代码必须符合 PSR-12/ESLint 规范
- 不得泄露密钥
- 输出仅包含有效 JSON

---

## 6️⃣ 提示正文（Prompt Body）
```text
你是一位资深 WordPress 插件工程师，…
【用户输入区标识符】
…
```
> 建议使用 Markdown code-block 包裹正文，以防渲染字符冲突。

---

## 7️⃣ 输出格式（Expected Output）
描述 AI 输出的结构/格式要求，例如：
```json
{
  "files": [
    { "path": "plugin.php", "content": "<?php … ?>" },
    { "path": "README.md", "content": "# 使用说明 …" }
  ],
  "instructions": "…"
}
```

---

## 8️⃣ 评估指标（Evaluation Rubric）
| 维度 | 满分 | 说明 |
|------|------|------|
| 准确性 | 5 | 是否满足业务需求 |
| 可用性 | 5 | 生成代码能否直接运行 |
| 清晰性 | 5 | 文档/注释是否易懂 |
| 一致性 | 5 | 与其他模块风格一致 |

---

## 9️⃣ 常见问题（FAQ）
- **Q:** 如何扩展功能 X？  
  **A:** 更新输入参数 `feature_flags`。
