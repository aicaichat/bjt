## 三、关键问题识别与优先级

### 🚨 P0级别（影响核心功能，必须立即修复）

1. **适配机型字段规范缺失**
   - 影响场景：选型页、购物车页
   - 风险：筛选功能异常，无法按机型查找备件
   - 解决方案：在name统一.csv中添加规范
   - 字段映射：适配机型 → app_model

2. **产品图片字段规范缺失**
   - 影响场景：选型页、购物车页
   - 风险：商品列表无图片显示，用户体验差
   - 解决方案：在name统一.csv中添加规范
   - 字段映射：产品图片 → image_url

3. **is_consumable字段类型不一致**
   - 影响场景：筛选功能
   - 风险：易损/非易损筛选逻辑错误
   - 当前问题：数据库是tinyint(1,2,3)，前端可能按boolean处理
   - 解决方案：前端添加类型守卫，统一为数字类型

### ⚠️ P1级别（数据一致性，应优先修复）

4. **✅ 智能Spec字段显示问题（已解决）**
   - 问题字段：Spec. ↔ Spec.(英制)
   - 解决方案：实现智能Spec字段，根据用户区域自动选择显示内容
   - 实现状态：✅ 已完成
   - 用户体验：统一显示为"Spec."，智能选择最适合的规格内容

5. **字段命名不一致问题**
   - 问题字段：
     - 包装尺寸cm ↔ 包装尺寸(cm)
     - 包装尺寸inch ↔ 包装尺寸(inch)
     - 单件净重kg ↔ 单件净重(kg)
     - 单件净重lbs ↔ 单件净重(lbs)
   - 解决方案：统一字段命名规范

6. **productId显示缺失**
   - 影响场景：购物车页面数据追踪
   - 解决方案：前端添加productId显示

7. **Unit字段缺失规范**

## 六、特殊处理说明

### 6.1 复合尺寸格式处理

对于"10*29*49"类型的尺寸数据：
- 识别格式：`*` `x` `×` 分隔符
- 显示方式：`"10*29*49 cm"` (保持原格式+单位)
- 支持维度：三维、二维、一维

### 6.2 is_consumable值映射

数据库值 → 前端显示：
- `1` → "易损" / "Consumable"
- `2` → "非易损" / "Non-consumable"  
- `3` → 不在筛选中显示，列表中隐藏

### 6.3 智能字段显示规范 ⭐

**🎯 核心要求**：备件页面字段根据用户区域智能选择显示内容，提供最佳用户体验

#### 智能Spec字段显示
**应用位置**：备件列表展示区域
**要求**：只显示一个Spec字段，根据用户区域智能选择显示内容

**📋 实现规则**：
```typescript
// 根据用户区域确定单位制
const unitSystem = (userRegion === 'na' || userRegion === 'au') ? 'imperial' : 'metric';

if (unitSystem === 'metric') {
  // 公制地区：优先显示spec，如果为空则fallback到spec_imperial
  return part.spec?.trim() || part.spec_imperial?.trim() || '请咨询客服';
} else {
  // 英制地区：优先显示spec_imperial，如果为空则fallback到spec
  return part.spec_imperial?.trim() || part.spec?.trim() || 'Please contact service';
}
```

#### 智能Tooltip字段显示
**应用位置**：详细信息悬浮层
**要求**：字段标签和内容都根据用户区域智能显示单位制

**📋 实现规则**：
```typescript
// 包装尺寸智能显示
const packageSizeLabel = `Package Size (${unitSystem === 'metric' ? 'cm' : 'inch'})`;
const packageSizeValue = unitSystem === 'metric' 
  ? (formatCompositeDimension(part.package_size_cm, 'cm') || 
     formatCompositeDimension(part.package_size_inch, 'inch') || 'Please contact service')
  : (formatCompositeDimension(part.package_size_inch, 'inch') || 
     formatCompositeDimension(part.package_size_cm, 'cm') || 'Please contact service');

// 重量智能显示
const weightLabel = `Net Weight (${unitSystem === 'metric' ? 'kg' : 'lbs'})`;
const weightValue = unitSystem === 'metric'
  ? (formatWeight(part.net_weight_kg, 'kg') || 
     formatWeight(part.net_weight_lbs, 'lbs') || 'Please contact service')
  : (formatWeight(part.net_weight_lbs, 'lbs') || 
     formatWeight(part.net_weight_kg, 'kg') || 'Please contact service');
```

**🌍 地区映射**：
- **英制地区**: 北美 (na)、澳洲 (au) → 优先显示 `spec_imperial`, `package_size_inch`, `net_weight_lbs`
- **公制地区**: 中国 (cn)、欧洲 (eu)、其他 → 优先显示 `spec`, `package_size_cm`, `net_weight_kg`

**✅ 显示要求**：
- 字段标签: 明确显示当前使用的单位制，如"Package Size (cm)"或"Net Weight (lbs)"
- 内容逻辑: 智能选择最符合用户地区习惯的数据，双重fallback确保有内容显示
- 容错处理: 如果两个单位制数据都为空，显示友好提示
- 用户体验: 用户只看到符合其地区习惯的单位制，避免混淆

**❌ 禁止行为**：
- 不得同时显示公制和英制的相同字段（如同时显示"Package Size (cm)"和"Package Size (inch)"）
- 不得在字段标签中忽略单位制说明
- 不得忽略用户区域偏好设置
- 不得在tooltip中显示超过3个必需字段
