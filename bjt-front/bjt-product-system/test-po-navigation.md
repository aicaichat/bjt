# PO页面导航问题修复测试指南

## 问题描述
用户报告从订单列表页面 (http://localhost:5173/orders) 点击"back to po"后，页面展示信息丢失了。

## 修复内容

### 1. 订单列表页面修复 (`frontend/src/pages/OrderList/index.tsx`)
- 修复了 `handleViewOrderDetail` 函数中的数据提取逻辑
- 从订单的 `shippingInfo` 和 `shipping_address` 字段中正确提取客户和运输信息
- 添加了数据完整性检查和默认值处理
- 为商品项目添加了 `spec` 和 `brand` 字段

### 2. PO页面修复 (`frontend/src/pages/PO/index.tsx`)
- 改进了数据接收和处理逻辑
- 添加了更详细的调试日志
- 增强了对空数据的处理，提供默认值
- 确保客户信息和运输信息正确显示

## 测试步骤

### 步骤1: 准备测试环境
1. 确保前端服务器运行在 http://localhost:5173
2. 确保有一些测试订单数据

### 步骤2: 测试订单列表页面
1. 访问 http://localhost:5173/orders
2. 检查是否能看到订单列表
3. 确认每个订单卡片上有"返回PO页面"按钮

### 步骤3: 测试PO页面导航
1. 在订单列表页面点击任一订单的"返回PO页面"按钮
2. 检查是否成功跳转到PO页面 (/po)
3. 检查PO页面是否显示以下信息：
   - 订单商品列表（应该显示订单中的所有商品）
   - Buyer信息（公司名称、联系人、地址、电话）
   - Ship To信息（运输地址、联系人、电话、备注）
   - 订单汇总信息（小计、运费、总计）

### 步骤4: 验证数据一致性
1. 对比订单列表页面显示的信息和PO页面显示的信息
2. 确认以下数据一致：
   - 商品数量
   - 商品名称和规格
   - 价格信息
   - 总金额

### 步骤5: 检查控制台日志
1. 打开浏览器开发者工具
2. 查看控制台是否有以下日志：
   ```
   🔧 [OrderList] 找到订单: [订单对象]
   🔧 [OrderList] 提取的客户信息: [客户信息对象]
   🔧 [OrderList] 提取的运输信息: [运输信息对象]
   🔧 [PO Page] 接收到的poData: [PO数据对象]
   🔧 [PO Page] 设置客户信息: [客户信息]
   🔧 [PO Page] 设置运输信息: [运输信息]
   ```

## 预期结果

### 修复前的问题
- PO页面显示空白或默认信息
- 客户信息显示为空
- 商品列表可能为空或不完整

### 修复后的预期结果
- PO页面正确显示订单信息
- Buyer区域显示实际的客户信息
- Ship To区域显示实际的运输信息
- 商品列表显示订单中的所有商品
- 所有价格和汇总信息正确显示

## 故障排除

### 如果PO页面仍然显示空信息
1. 检查控制台日志，查看数据提取过程
2. 确认订单数据结构是否符合预期
3. 检查 `shippingInfo` 字段的格式

### 如果页面跳转失败
1. 检查路由配置
2. 确认订单ID是否有效
3. 查看控制台是否有JavaScript错误

### 如果数据不完整
1. 检查订单原始数据的完整性
2. 确认数据提取逻辑是否覆盖所有字段格式
3. 查看默认值是否正确设置

## 调试提示

1. 使用浏览器开发者工具的Network标签查看API请求
2. 在控制台运行以下命令查看订单数据结构：
   ```javascript
   // 在订单列表页面
   console.log('订单数据:', orders);
   ```
3. 在PO页面检查接收到的数据：
   ```javascript
   // 在PO页面
   console.log('location.state:', history.location.state);
   ```

修复完成后，从订单列表页面点击"返回PO页面"应该能正确显示完整的订单信息，不再出现数据丢失的问题。
