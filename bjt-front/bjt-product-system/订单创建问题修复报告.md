# 订单创建问题修复报告

## 问题描述

用户报告BJT产品管理系统中显示订单创建成功（订单号：`ORD-20250623-RGT9H0`），但实际上订单没有被保存到后端数据库中。

## 问题分析

### 根本原因

1. **Mock数据模式默认启用**：
   - 环境变量 `VITE_USE_MOCK_DATA` 未正确设置
   - 前端默认使用Mock数据模式，不会调用真实API

2. **订单号生成逻辑混乱**：
   - `orderService.submitOrder()` 在Mock模式下使用 `generateMockOrderId()` 生成简单4位数订单号
   - PO页面使用自己的 `generatePONumber()` 生成日期格式订单号
   - 两者格式不一致导致混乱

3. **API调用缺失**：
   - `submitOrder` 方法在非Mock模式下没有实现真实的API调用
   - 只是返回硬编码的 `'api-order-id'`

### 问题表现

- 前端显示订单创建成功
- 生成看似合理的订单号（如 `ORD-20250623-RGT9H0`）
- 但实际没有调用后端API
- 数据库中没有对应的订单记录

### 2. 统一订单号生成格式

**文件**: `frontend/src/services/mocks/orders.mocks.ts`

**修改内容**:
- 修改 `generateMockOrderId` 函数，使其生成与后端一致的格式

```typescript
export const generateMockOrderId = (): string => {
  const date = new Date();
  const year = date.getFullYear();
  const month = String(date.getMonth() + 1).padStart(2, '0');
  const day = String(date.getDate()).padStart(2, '0');
  // 生成6位随机字符串，与后端格式一致
  const randomString = Math.random().toString(36).substring(2, 8).toUpperCase().padStart(6, '0');
  return `ORD-${year}${month}${day}-${randomString}`;
};
```
